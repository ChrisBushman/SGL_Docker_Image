1.変更・追加概略
    バージョン1.02以前からの変更・追加は以下の２点についてです。
    最初に主な変更点を説明します。その後に以下の２点の詳細な変更・
    追加を変更マニュアルとして記します。

    ・ゲーム作成基準（ペリフェラル）への対応による変更

 1.1.ゲーム作成基準（ペリフェラル）への対応による変更

    ゲーム作成基準へ対応できるようにペリフェラルの取得の仕様を一部変
    更しました。主な変更点は以下のとおりです。
    各ゲーム毎にライブラリ使用方法の自由度をあげるため、前バージョン
    より大幅に低水準化しています。関数の数は前バージョンと同じです。
    関数名称は前バージョンと見分けがつくよう変更してあります。

    **☆重要☆******************************************************
    *   Ver1.02以前のライブラリはゲーム作成基準に合わせることができ*
    *   ないので、必ずVer1.03以降のライブラリへ移行してください。  *
    ****************************************************************

    a)マルチタップ情報の出力追加
        ペリフェラルデータの接続端子の情報が必要なため。
        →PER_LGetPer()関数の項を参照

    b)ペリフェラルサイズの出力追加
        ペリフェラルの種別判定に必要なため。
        →PER_LGetPer()関数の項を参照

    c)PUSH(前回未押下現在押下)データの出力の削除。
        メモリ効率を最適化できるようにライブラリから削除。

    d)ペリフェラルデータをほぼ加工しないで出力するよう修正。
        1つのゲーム内で異なるペリフェラルを使用できるようにするため。
        ( 例 -> 1P = アナログ、2P = マウス のゲーム  ）
        →データ仕様の項を参照


2.変更マニュアル

    2.1.注意

        a)２フレーム以上のゲームでの注意点
            ２フレーム以上（PER_LInit関数で設定するV-BLANKスキップ数
            で１以上を設定する）の場合、本ライブラリでは最後のフレー
            ムのみペリフェラルの取得を行います。
            この仕様では、途中のフレームのペリフェラルデータを取得し
            ないため、エッジ（前回未押下現在押下ボタン）の検出ができ
            ない場合があります。
            シビアなエッジのチェックが必要な場合は、V-BLANKスキップ数
            を0にして、毎インタラプトでPER_LGetPer関数を実行してくだ
            さい。

        b)配布マニュアル内にて
          「PER_LGetPer関数はV-BLANK OUT直後に実行してください」
           と記述していましたが、VDP2ライブラリの SCL_VblankEnd関数を
           使用する場合は、PER_LGetPer関数を SCL_VblankEnd関数よりも
           後に実行してください。
           SCL_VblankEnd関数の実行タイミングが遅いとスプライトのフレ
           ームチェンジが次のタイミングになってしまい、画面の動きが遅
           くなってしまいます。


    2.2.コーリングシーケンスについて

        サンプルプログラムを参考にしてください。
        サンプルプログラムは関数の使い方を知っていただくのが目的です。
        そのためゲーム作成基準に合っていない部分があります。
        例：ボタン使用方法の悪い例（Ａ：決定、Ｂ：キャンセル、Ｃ：無反応）
                    ↓作成基準対応－Ｃボタン優先の原則
            ボタン使用方法の推奨例（Ａ：決定、Ｂ：キャンセル、Ｃ：決定）


3.データ仕様

      3.1.ペリフェラルデータ
          出力を以下のように変更しました。

      3.2.ペリフェラル１個当たりのデータの構造

          +-ペリフェラルタイプ
          |    +-ペリフェラルサイズ
          |    |    +-DATA1
          |    |    |    +-DATA2       DATAn-+
          |    |    |    |                   |
        +----+----+----+----+              +----+
        | TP | SZ | D1 | D2 |・・・・・・・| Dn |
        +----+----+----+----+              +----+
         <-->
          1 Byte
         <-------------------------------------->
              (n + 2)Byte     n はPER_LInit()にて指定したsizeに等しい

           ・ペリフェラルタイプ
               PER_ID_NCON_UNKNOWN /* 未接続 or SMPC UNKNOWN    */
               PER_ID_DGT          /* デジタルデバイス          */
               PER_ID_ANL          /* アナログデバイス          */
               PER_ID_PNT          /* ポインティングデバイス    */
               PER_ID_KBD          /* キーボード                */
               PER_ID_MD           /* メガドライブＰＡＤ        */

           ・ペリフェラルサイズ
               PER_SIZE_NCON_15    /* 未接続 or 15バイトデバイス*/
               PER_SIZE_DGT        /* デジタルデバイス          */
               PER_SIZE_PNT        /* ポインティングデバイス    */
               PER_SIZE_KBD        /* キーボード                */
               PER_SIZE_M3BP       /* メガドライブ3ボタンパッド */
               PER_SIZE_M6BP       /* メガドライブ6ボタンパッド */
               0x0A (注)           /* バーチャガン              */
               0x03                /* ハンドルコントローラー         */
               0x05                /* ミッションスティック(3軸)      */
               0x09                /* ミッションスティック(6軸)      */
               0x06                /* マルチコントローラー(アナログ) */
              (注) バーチャガンのペリフェラルサイズは、マルチタップ接続の
                   場合のみ返ります。
                   本体に直接接続された場合には、マルチタップ情報に
                   バーチャガンのＩＤが返ります。

           ・DATA1・・・DATAn（ n Byte )
               ペリフェラルデータ
                 各ペリフェラルのデータフォーマットについては、
                 「SMPC ハードウェアマニュアル」等を参照して下さい．


      3.3.ペリフェラルデータ全体のデータの構造
        上記のデータが、本体端子のコネクタ数分出力されます。
        本体端子のコネクタ数は、後述のマルチタップ情報に含まれます。


4.マルチタップ情報→PER_LGetPer関数の説明を参照


    4.1.関数仕様変更

       a.PER_LInit()関数

       使用方法  (割込み処理内およびVブランク期間内では実行しないで下さい)
          ret =  PER_LInit( kind, num, size, work, v_blank);
                 PerKind   kind
                 PerNum    num
                 PerSize   size
                 Uint8     work[worksize]
                 Uint8     v_blank
       入力
          kind            ：イントバック種別
              PER_KD_SYS    :システムデータ取得
              PER_KD_PER    :ペリフェラルデータ取得
              PER_KD_PERTIM :ペリフェラルデータ取得+時刻データ取得
          num             ：必要ペリフェラル数(6～30の範囲)
          size            ：必要なペリフェラルデータのサイズ(2～15 の範囲)
          work[WORKSIZE]  ：ワーク領域（必ずグローバル変数で宣言してください)
          v_blank         ：V-BLANKスキップ数。
                            スキップしない場合は 0 を指定して下さい。
       出力
          なし
       関数値
          実行結果
              PER_INT_ERR : イントバックコマンド発行に失敗しました
              PER_INT_OK  : 正常に終了しました

       ワーク領域サイズ(バイト単位)の計算方法
          WORKSIZE = (num * (size + 2) * 2) + size

          確保する必要があるsizeの値は、使用するペリフェラルによって
          異なります。
          各ペリフェラル毎に必要な sizeの値は、次の通りです。

                ペリフェラルタイプ                   size
                -----------------------------------------
                デジタルデバイス                      2
                アナログデバイス                     3～9
                    ハンドル                          3
                    ミッションSTICK(3軸)              5
                    ミッションSTICK(6軸)              9
                    マルチコントローラー(アナログ)    6
                ポインティングデバイス                3
                キーボードデバイス                    4
                メガドライブ3ボタンパッド             1
                メガドライブ6ボタンパッド             2
                -----------------------------------------

          設定したsizeよりも大きいデータサイズを持つペリフェラルが
          接続された場合は、size以降のデータは参照できません。
          それ以外は特に問題ありません。
          例）size = 2 の時にアナログデバイスが接続された場合
             アナログデバイス中の「デジタル情報」：参照可
             アナログデバイス中の「アナログ情報」：参照不可

       補足１）ワーク領域サイズの算出には下記の追加されたマクロを利用する
             事も可能です。
             ・PER_WORK_SIZE(num, size)  → Uint8 で確保する場合用
             ・PER_WORK_SIZE2(num, size) → Uint16 で確保する場合用
             ・PER_WORK_SIZE4(num, size) → Uint32 で確保する場合用

       補足２）
             ペリフェラルの返すデジタル情報は、16Bitのデータです。
             デジタルデータを 16Bitの構造体メンバとしてアクセスする場合は、
             PER_LInit に渡すワーク領域を Uint16 または Uint32 で確保する
             様にし、データサイズの指定(size)は２の倍数で指定して下さい。

       注意事項
          ・PER_Init関数は削除されました．かならずPER_LInit関数を
            使用して下さい．


    4.2. PER_LGetPer()関数

        使用方法(Vブランク終了割込み中で使用して下さい)
           ret = PER_LGetPer( &output_dt, &mul_info);
                 PerGetPer *output_dt
                 PerMulInfo *mul_info
        入力
           なし
        出力
           output_dt：ペリフェラルデータ取得アドレス
                      (NULL=取得失敗）
           mul_info[]：マルチタップ情報
                     mul_info[0]:本体端子１のマルチタップ情報
                     mul_info[1]:本体端子２のマルチタップ情報
       関数値
           実行結果
              PER_INT_ERR : イントバックコマンド発行に失敗しました
              PER_INT_OK  : 正常に終了しました

        マルチタップ情報の詳細

          本体のペリフェラル接続端子の接続状態を示します。
          各端子ごとに次の情報を取得することができます。

            typedef struct {
                PerMulId    id;     /* マルチタップID     */
                PerMulCon   con;    /* コネクタ数         */
            }PerMulInfo;

         [取得例]
            PerGetPer  *per_data;
            PerMulInfo *mul_info;
            PER_LGetPer(&per_data, &mul_info);
                mul_info[0].id   本体端子１のマルチタップＩＤ
                mul_info[0].con  本体端子１のコネクタ数
                mul_info[1].id   本体端子２のマルチタップＩＤ
                mul_info[1].con  本体端子２のコネクタ数

         [詳細]
          ・マルチタップID
              マルチタップ接続   : (00～E0) シンボル未定義
              未接続 or 直接接続 : (F0)     PER_MID_NCON_ONE
              UNKNOWNデバイス    : (MD-PID) シンボル未定義
                        バーチャガン : (A0)     シンボル未定義

          ・コネクタ数
              未接続 or UNKNOWNデバイス  : (00) PER_MCON_NCON_UNKNOWN
              直接接続                   : (01)     シンボル未定義
              接続マルチタップコネクタ数 : (02～0F) シンボル未定義

            [備考]
             現在サポートされているマルチタップは次の２種類です。
               ・マルチターミナル６ (サターン用ペリフェラルを接続可能)
                  マルチタップID = 10, コネクタ数 = 06
               ・セガタップ (メガドライブ用ペリフェラルを接続可能)
                  マルチタップID = 00, コネクタ数 = 04

    4.3.注意事項

        ・PER_GetPer関数は削除されました．かならずPER_LGetPer関数を
          使用して下さい．
        ・ペリフェラルデータはマルチタップ情報に返ってくるコネクタ
          数の範囲のみ値を保証します。
          よってペリフェラルデータを参照するときは必ずマルチタップ
          コネクタ数から参照範囲を決めてください。
        ・未接続の時はペリフェラルデータの初期化を行っていません。
          必ず 接続・未接続のチェックを行ってからペリフェラルデータ
          の参照をするようにして下さい。

          [チェック手順]

           a)マルチタップ情報から、２つの本体端子の接続状況を確認する。
             未接続 OR 直接接続 OR UNKNOWNペリフェラル
             →ペリフェラルデータの先頭の１つが有効
                マルチタップ接続
             →ペリフェラルデータの先頭からコネクタ数だけ有効
                タップの各端子の接続状態は、それぞれの端子の
                ペリフェラルタイプ,ペリフェラルサイズから確認


5.トラブルシューティング

   5.1.ペリフェラルデータが取得できない。
        V-BLANK OUTから次のV-BLANK INまでの間に．．
        ・SHの割り込みマスクが15になっていないか？
            割り込みマスクが15になっているとSMPC割り込み（その他の割
            り込みも）を受け付けることができません。
            SMPCの割り込み優先度より低い割り込みマスクを設定してくだ
            さい。

        ・SCUの割り込みマスクのSMPC割り込みビット位置が1（禁止）に
          なっていないか？
            割り込み禁止になっているとSMPC割り込みを受け付けることが
            できません。0（許可）にしてください。

        ・SMPC割り込み優先度より高い割り込みが長時間実行されていないか？
            優先順位の高い割り込み処理中，は優先度の低い割り込みを
            受け付けることができません。
            優先度の高い割り込み処理を長く実行しなくするか、システム
            ライブラリの割り込み優先順位変更ルーチンを使用し，SMPC割
            り込みが受け付けれるようにしてください。

             ※割り込み優先度はハード固有値とシステムライブラリの
               設定値の２つがあります。詳しくはシステムライブラリ
               とSCUハードウェアマニュアルをご覧ください。

   5.2.マルチタップに接続したペリフェラルが突然操作不可能になる．

        本ライブラリにてペリフェラル情報を取得する際、マルチタップを
        使用していると、接続されているペリフェラルでの操作が突然不可
        能になる現象が確認されています．
        実際には、ライブラリがペリフェラル未接続の値を返しており、ペ
        リフェラルかマルチタップを一度抜いてから挿し直すまで、正常に
        戻りません．
        この現象は、Vブランク中の処理が重い時に発生します．
        (V-RAMへのデータ転送など）
        Vブランク中の処理を軽減するように変更して下さい．

        それでもこの現象が回避できなかった場合は、次のような対策を
        施してください。
        ・PER_LInit()で設定するデータ取得モードを、「PER_KD_PERTIM」から
         「PER_KD_PER」に変更してください．
        ・システムライブラリのSCUの割込み優先度変更機能を使用して、
          SMPC割込みの優先度を高くしてください．

    もしも以上の変更を行っても現象が発生する場合は、「未接続」の
    ステータスが返ってきた際に PER_LInit関数を再度実行するように
    してください．
    （数回繰り返しても「未接続」が返る場合に、本当に未接続である
      とみなすようにして下さい．）

   5.3. PER_LInit()の実行について
     PER_LInit()は、実行時に必ず成功するとは限らず、失敗する場合もあります。
     必ずPER_LInit()の関数値を確認し、リトライ処理を行うようにして下さい。
     失敗した場合には、再度PER_LInit()を実行する必要があります。
     ただし、同一フレーム内での再実行は禁止ですので、次フレーム以降で
     再実行して下さい。


6.ライブラリ変更履歴
  6.1. Ver.1.00からVer.1.03までの不具合修正について

  6.1.1. Ver.1.00から1.03までの履歴
         Ver1.03の不良の対策を以下のように行いました。

        a)manper.docの記述誤り
          174行目のPER_LInitのワークエリア計算方法を誤って記述していました。

        b)マウスのペリフェラルID出力値の誤り
          マウスのペリフェラルIDを誤って、「E0」で出力していました。
          正しく「20」(PER_ID_PNT)を出力するよう修正しました。


        c)Ver1.03によるペリフェラルデータ出力仕様変更について
          PerXxxInfo, PerXxxDataデータ型は削除しました。

          ※但し、PerXxxDataのビット位置定数は名称を変更して残してあ
            ります。ビット位置はバイト単位でアクセスしたときのもので
            す。詳細は sega_per.hをご覧ください。
                (例) PER_DGT_U --> PER_LDGT_U

          ※マウスデータのデジタルデータ作成機能は削除しました。
            Ver1.02では以下のようにしてマウスのデジタルデータを作成
            していました。参考にしてください。
               (1)毎回の取得で以下のことを行う。
                   ・Yデータがマイナスであるとき
                       DOWN加算変数へY移動絶対値を加算
                   ・Yデータがプラスであるとき
                       UP加算変数へY移動絶対値を加算
                   ・Xデータがマイナスであるとき
                       LEFT加算変数へX移動絶対値を加算
                   ・Xデータがマイナスであるとき
                       RIGHT加算変数へX移動絶対値を加算

                   それぞれ加算変数が256以上になったときビットを押下
                   状態にする。押下状態にした加算変数は0クリアする。


            Ver1.02以前とVer1.03以降ではペリフェラル出力データが
            異なります。
            Ver1.03以降では、「マルチタップ情報」をもとにペリフェラル
            出力データを参照してください。

            詳しくは本ドキュメント内の「マルチタップ情報」の項を
            参照して下さい．

           [具体例]

          以下の接続状態時のVer1.02以前とVer1.03以降のペリフェラル
          出力データの違いを示します。

          ・接続状態
              本体端子1=未接続
              本体端子2=デジタルデバイス

          ・出力結果（Ver1.02以前）
              配列 0 = デジタルデバイス
              配列 1 = 不定

          ・出力結果（Ver1.03以降）
              配列 0 = 不定   ※注意
              配列 1 = デジタルデバイス
              マルチタップ情報
                本体端子1マルチタップID = PER_MID_NCON_ONE(未接続の意味)
                本体端子1コネクタ数 = PER_MCON_NCON_UNKNOWN(未接続)
                本体端子2マルチタップID = PER_MID_NCON_ONE(直接接続の意味)
                本体端子2コネクタ数 = 01

            上記のように、Ver1.02以前とVer1.03以降ではペリフェラル出
            力データが異なります。
            かならず「マルチタップ情報」をもとにペリフェラル出力デー
            タを参照してください。
            (マルチタップ情報追加の理由は、ペリフェラル作成基準
             を守るためです。)
            ※注意
            ペリフェラルの接続/未接続チェックは、ペリフェラルＩＤだけでは
            不完全となります。
            必ずマルチタップ情報と併せて接続チェックを行う様にして下さい。


  6.1.2.Ver.1.00からVer.1.03までの変更履歴補足

            ・コンパイルオプションの変更
              ライブラリのコンパイルオプションの/SPを/NOSPへ変更しました。
              理由は、/SP でコンパイルすると関数がインライン展開されてしま
             うのでデバッグ時に混乱を招く恐れがあるためです。

           ・Ver1.01(1994-08-22)のサンプルでSCUの割り込みステータス
             レジスタを使用していました。しかし、このレジスタはハー
             ドウェアの仕様変更に伴い使用禁止になりました。
