１．  概要
１．１  内容
  ＰＣＭ・ＡＤＰＣＭ再生ライブラリは、サターンでのＰＣＭストリーム再生をサポー
トする。
  「ＰＣＭ・ＡＤＰＣＭ再生ライブラリ Ver.1.26」では、新ファイル形式の「Saturn
PCM ファイル」へ対応する。
  SaturnPCM ファイル再生は、処理速度が速く、また作業領域を多く取らないため、
より高度なアプリケーションに適用できる。

１．２  Ver.1.26 の特徴
（１） Ver.1.17 への上位互換性
  (a)「ＰＣＭ・ＡＤＰＣＭ再生ライブラリ Ver.1.17」を使うアプリケーションで、
      プログラムを修正することなくそのまま利用できる。
  (b) ライブラリ利用はこれまでと同様の手順で行える。
    ※ＰＣＭワーク構造体が変更されているため、アプリケーションの再コンパイルが
      必要。

（２） Ver.1.17 からの機能改善
  (a) SHC コンパイラ Ver.3.0F 対応
  (b) SHC コンパイルオプション「div」を「cpu」とした。
     （Ver.1.20 では「peripheral」としたが、SHC標準ライブラリ除算器関連の
       バグのため、Ver.1.21 で「cpu」とした）
  (c) 不要なコードの削除と処理方法の最適化。
  (d) 障害対応。
    1>  PCM_PreloadFile 関数の戻り値を正しくした。
	2>  サイズが４倍数でないとき最後まで再生されないバグを修正した。

（３）SaturnPCM ファイルへの対応
  (a) 新ファイル形式の SaturnPCM ファイルへ対応。
  (b) SaturnPCM ファイル再生には以下の特徴がある。
    ・高速処理
      ＣＤバッファから直接サウンドメモリに SCU-DMA 転送するため、再生ライブラリ
      のＣＰＵ負荷が軽減される。
    ・省作業領域
      リングバッファを必要としないため、メインメモリを圧迫することがない。
    ・同期再生
      映像再生との同期などが容易に行える。

（４）Ver. 1.26からの新機能
      これまでのPCM再生は、ダイナミックレベル8段階でしたが、Ver. 1.25より
      サウンドドライバのTotalLevelパラメータに対応したため、256段階の
      ボリュームが可能。
      但し、Total Level値の変更はユーザアプリケーション側で、直接ハンドル
      のパラメータを変更する必要があります。

２．  仕様
  SaturnPCM ファイル再生の仕様をまとめた。
（AIFF / ADPCM / CD-ROM XA Audio ファイル再生の仕様はこれまでと同様）

  サンプリング周波数  : 最大 44.1 KHz
  量子化ビット数      : 8 bit、16 bit
  チャネル数          : モノラル、ステレオ
  再生モード          : ファイル再生モード（ファイルシステムを使用）
                        ストリーム再生モード（ストリームを使用）
  機能                : 連続再生、マルチ再生
                        ポーズ、ボリューム／パンの指定
  連続再生時間        : 最大１時間
  使用ライブラリ      : ファイルシステム、ストリーム、DMA ライブラリ
  使用資源            : CPU タイマ（ FRT ）
                        SCU-DMA（チャネル0）※１
                        CPU-DMA（チャネル1）※１
  ワークエリア        : ワークバッファ： 528 byte（ＰＣＭワーク）※２
                        拡張ワーク    ：2048 byte（SaturnPCM 再生用）
                        PCM バッファ  ：4096×2～4096×16 sample / ch  ※３
                        ポーズ処理用  ：4096 sample～ PCM バッファサイズ

※１  ＣＤバッファからＰＣＭバッファへの転送方式は、ソフトウェア転送 ／
      CPU-DMA ／ SCU-DMA より選択可能。
※２  Ver.1.17 よりＰＣＭワーク構造体のサイズが増加。
※３  SaturnPCM 再生の場合PCMバッファの最小サイズは4096×4となる。


３．  データ作成
（１）SaturnPCM 変換ツール
  SaturnPCM ファイルは AIFF ファイルより、変換ツール「aif2sap.exe」により作成
する。

［書式］
    aif2sap aiffile [sapfile]
        aiffile : AIFF ファイル名
        sapfile : SaturnPCM ファイル名

［機能］
  AIFF ファイルを SaturnPCM ファイル（ SAP ファイル）へ変換する。
  SaturnPCM ファイル名を入力しなかった場合、AIFF ファイル名のベース名に拡張子
「SAP」を付加したファイル名で SaturnPCM ファイルが作成される。

［使用例］
  (a) AIFF ファイル「sample1.aif」より SaturnPCM ファイル「sample1.sap」を作成
      する。
        c:\>aif2sap sample1.aif

（２）データフォーマット
  SaturnPCM ファイルの基本フォーマットは次のとおり。

  (a) セクタバウンダリ構造をとる。
  (b) ＰＣＭデータは 4096 sample バウンダリで各チャネルごとにパックする。

  《例》 8 bit、ステレオ
    ┌───┬───────────────────────┐
    │      │L dat0│R dat0│L dat1│R dat1│      │      │
    └───┴───────────────────────┘
    │ヘッダ│←               ＰＣＭデータ               →│
     2048 byte                2048 ×Ｎ byte


４．  プログラム作成
４．１  処理手順
  SaturnPCM ファイルは、ファイル再生モード（ファイルシステムを使用）とストリー
ム再生モード（ストリームを使用）の２種類の再生モードをサポートする。

（１）ファイル再生
  ＰＣＭライブラリ初期化後に、PCM_DeclareUseSapGfs 関数を呼び出し、ファイル再生
モードでの SaturnPCM ファイル再生を宣言する。

《例》
	/*  ワークバッファ  */
	static	PcmWork	g_movie_work;

	/*  SaturnPCM ファイル再生用拡張ワークエリア  */
	static	Sint8	g_sap_work[PCM_SAP_XWORK_SIZE];

	void	samplePcmStm(void)
	{
		PcmHn 			pcm;
		GfsHn			gfs;
		PcmCreatePara	para;

		/*  ＰＣＭライブラリの初期化  */
		PCM_init();

		/*  SaturnPCM をファイル再生モードで使用宣言する  */
		PCM_DeclareUseSapGfs();

		/*  ファイルオープン  */
		gfs = gfsOpen("SAMPLE.SAP");

		/*  ＰＣＭハンドルを生成する  */
		PCM_PARA_WORK(&para) = (struct PcmWork *)&g_movie_work;
		PCM_PARA_XWORK_ADDR(&para) = g_sap_work;
		PCM_PARA_XWORK_SIZE(&para) = PCM_SAP_XWORK_SIZE;
		PCM_PARA_PCM_ADDR(&para)   = (void *)0x25a20000;
		PCM_PARA_PCM_SIZE(&para)   = 4096L*2;
		pcm = PCM_CreateGfsHandle(&para, gfs);

		/*  ＣＤバッファからサウンドメモリへの転送方法を指定  */
	    PCM_SetTrModeCd(PCM_TRMODE_SCU);

		/*  ループ回数の指定  */
		PCM_SetLoop(pcm, 16);

		/*  SaturnPCM 再生開始  */
		PCM_Start();

		/*  再生タスクの実行  */
		for (;;) {
			/*  再生タスク  */
			PCM_Task(pcm);

			/* その他の処理  */
			if (PCM_GetPlayStatus(pcm) == PCM_STAT_PLAY_END) {
				break;
			}
		}

		/*  ハンドルの消去  */
		PCM_DestroyGfsHandle(pcm);

		/*  ファイルのクローズ  */
		gfsClose(gfs);

		return;
	}

（２）ストリーム再生
  ＰＣＭライブラリ初期化後に、PCM_DeclareUseSapStm 関数を呼び出し、ストリーム
再生モードでの SaturnPCM ファイル再生を宣言する。

《例》

	/*  ワークバッファ  */
	static	PcmWork	g_movie_work;

	/*  SaturnPCM ファイル再生用拡張ワークエリア  */
	static	Sint8	g_sap_work[PCM_SAP_XWORK_SIZE];

	void	samplePcmStm(void)
	{
		PcmHn 			pcm;
		StmHn			stm;
		PcmCreatePara	para;

		/*  ＰＣＭライブラリの初期化  */
		PCM_init();

		/*  SaturnPCM をストリーム再生モードで使用宣言する  */
	    PCM_DeclareUseSapStm();

		/*  ストリームオープン  */
		stm = stmOpen("SAMPLE.SAP");

		/*  ＰＣＭハンドルを生成する  */
		PCM_PARA_WORK(&para) = (struct PcmWork *)&g_movie_work;
		PCM_PARA_XWORK_ADDR(&para) = g_sap_work;
		PCM_PARA_XWORK_SIZE(&para) = PCM_SAP_XWORK_SIZE;
		PCM_PARA_PCM_ADDR(&para)   = (void *)0x25a20000;
		PCM_PARA_PCM_SIZE(&para)   = 4096L*2;
		pcm = PCM_CreateStmHandle(&para, stm);

		/*  ＣＤバッファからサウンドメモリへの転送方法を指定  */
	    PCM_SetTrModeCd(PCM_TRMODE_SCU);

		/*  SaturnPCM 再生開始  */
		PCM_Start();

		/*  再生タスクの実行  */
		for (;;) {
			/*  サーバの実行  */
			STM_ExecServer();

			/*  再生タスク  */
			PCM_Task(pcm);

			/* その他の処理  */
			if (PCM_GetPlayStatus(pcm) == PCM_STAT_PLAY_END) {
				break;
			}
		}

		/*  ハンドルの消去  */
		PCM_DestroyStmHandle(pcm);

		/*  ストリームクローズ  */
		stmClose(stm);

		return;
	}


４．２  プログラミング上の注意事項
  本ライブラリを使って再生する時の注意事項を示す。

（１）ファイル形式
  (a) SaturnPCM ファイルと AIFF / ADPCM / CD-ROM XA Audio ファイルを同時に使用
     することはできない。PCM_DeclareUseSapGfs 関数、PCM_DeclareUseSapStm 関数
     により再生する。
     この時、再生するＰＣＭファイルはすべて SaturnPCM ファイルが対象となる。
  (b) AIFF / ADPCM / CD-ROM XA Audio ファイルを再生する場合は、改めてＰＣＭ
      ライブラリの初期化を行うか、PCM_UnDeclareUseSapGfs 関数、
      PCM_UnDeclareUseSapStm 関数により使用宣言を取り消す。

（２）使用資源に関して
  (a) SaturnPCM ファイルの再生には、SCU-DMA（チャネル0） と CPU タイマを使用
      する。SaturnPCM ファイル再生時は、SCU-DMA および CPU タイマは使用しない
      こと。
  (b) ＣＤバッファからサウンドメモリへの転送方式を PCM_SetTrModeCd 関数により
      変更することができる。デフォルトでは SCU-DMA 転送となっているので、これ
      を変更することができる。

（３）ワークエリア
  SatunPCM ファイル再生時は、リングバッファを必要とせず、代わりに拡張ワークが
必要となる。
  AIFF / ADPCM / CD-ROM XA Audio ファイル再生時は、これまでと同様にリングバッ
ファを使用する。

  ワークバッファ： 528 byte（ PCM ワーク）
  リングバッファ：最低 (セクタ数)×10 byte （ AIFF / ADPCM / CD-ROM XA Audio ）
  拡張ワーク    ：2048 byte                （ SaturnPCM ）
  PCM バッファ  ：4096×2～4096×16 sample / ch （ SaturnPCM 以外）
                  4096×4～4096×16 sample / ch （ SaturnPCM ）
  ポーズ処理用  ：4096 sample～PCM バッファサイズ

（４）ＰＣＭタスク
   (a) PCM_Task 関数は、少なくともＶブランク割り込みの頻度（１回/１６ｍｓ）と
      同等以上の頻度で、定期的にコールすること。
      同じ音が２回なる場合は、PCM_Task の頻度が少なすぎる可能性がある。
   (b) PCM_Set1TaskSample 関数により、１回のタスクで処理する量の上限を設定する
      ことができる。
      メインループの処理が重く、PCM_Task 関数の呼び出し間隔が長くなってしまう
      場合、１回あたりのタスク処理量を設定することで、同じ音が２回なるなどの
      障害が回避できる。
    ※タスク処理量はデータ読み込み量と関連するので、やみくもに大きな値を設定
      することはできない。データ読み込み量との調節が必要にある。
       PCM_Task 関数の呼び出し頻度を上げることが最も確実な方法である。

    ※ＰＣＭワーク構造体が変更されているため、アプリケーションの再コンパイルが

７．変更履歴
Ver.1.00 から Ver.1.10への変更点
      1) ライブラリ名称を変更しました。
        ［旧名称］「ＰＣＭ再生ライブラリ」
        ［新名称］「ＰＣＭ・ＡＤＰＣＭ再生ライブラリ」
      2) ＡＤＰＣＭ再生に対応しました。
      3) タスク関数の仕様を変更しました。
        ［旧仕様］４Ｖブランクに１回以上の頻度でコール。
                  １回のタスクで処理する量は、最大PCMバッファの半分の量
        ［新仕様］１Ｖブランクに１回以上の頻度でコール。
                  １回のタスクで処理する量は、最大4096サンプル分の量
      4) ADPCM使用宣言関数 PCM_DeclareUseAdpcm を追加しました。
          宣言がなければ、ADPCM伸張ライブラリがリンクされない仕組みにしてあります。

Ver.1.10 から Ver.1.11への変更点
      1) 添付している ADPCM伸張ライブラリが Ver1.00 から Ver1.01 になりました。
           Ver1.00 では、リンクエラーが発生するケースがありました。
      ※ ＰＣＭ・ＡＤＰＣＭ再生ライブラリ自体は全く変更していません。

Ver.1.11 から Ver.1.12への変更点
      1) 次のエラーチェックを追加しました。
          PCM_ERR_TOO_SMALL_PCMBUF : 「ＰＣＭバッファサイズが小さすぎ」
          PCM_ERR_ILL_SIZE_PCMBUF  : 「ＰＣＭバッファサイズが不正」
      2) セクションに関して、次の修正をしました。
        1.初期化データ領域（Ｄセクション）を使用しないように修正しました。
      3) 次のバグを修正しました。
        1.ストリームシステムを使って再生している時に、STM_SetExecGrp をコール
          すると、この関数から戻らない場合があり、修正しました。
          ストリームの消費速度，ストックに余裕があれば、再生中に一時的にスト
          リームグループを変更し、他のストリムーグループのデータを読むことが
          できるようになりました。

Ver.1.12 から Ver.1.13への変更点
      1) タスク関数の仕様を変更しました。
         ストリーム再生モードにおいて、以前は PCM_Task 内で STM_ExecServer 
         をコールしていましたが、STM_ExecServer は アプリケーション側がコール
         するように仕様変更しました。
         旧バージョンと同等の動作を行うには、PCM_Task の直前で STM_ExecServer 
         をコールして下さい。複数のＰＣＭハンドルがあり、PCM_Task を連続して
         コールする場合でも STM_ExecServer は１回のコールで十分です。
         場合によっては STM_ExecServer の代わりに、ＣＤブロックからの転送だけ
         を行う STM_ExecTrans をコールすることもできます。
        ［旧仕様］１回のタスクで処理する量は、最大4096[sample/1ch]。
                  ストリーム再生時、ライブラリ側が STM_ExecServer をコール。
        ［新仕様］１回のタスクで処理する量は調節可能。デフォルト値 1024[sample/1ch]。
                  ストリーム再生時、アプリケーション側が STM_ExecServer 又は 
                  STM_ExecTrans をコール。
      2) １回のタスク関数が処理する量の調節
         PCM_Set1TaskSample で１回のタスクで処理する量の上限を設定できます。
         これによりタスク関数の負荷を安定させることができます。
      3) ＰＣＭ再生開始,停止条件の設定
         PCM_SetStartTrgSize, PCM_SetStartTrgSample などで、再生開始条件を
         きびしく設定すれば、再生開始後、データ供給が不安定でも再生の安全性が
         高くなります。

Ver.1.13 から Ver.1.14への変更点
      1) 次のバグを修正しました。
        ＡＩＦＦのステレオ再生時に、「つっ」とノイズが入る場合があり、修正し
        ました。

Ver.1.14 から Ver.1.15への変更点
      1) ファイル再生モードのデータ転送処理(CPUDMAの場合)の改善
        ３回のタスクコールで１回分の最大転送セクタ数の転送をしていました。
        ２回のタスクコールで１回分の転送をするように修正しました。
      2) ループ再生機能の追加
        PCM_SetLoop で、ループする回数を指定します。デフォルト値１回。
        メモリ再生モード、または、ファイル再生モードで使用して下さい。
        メモリ再生モードの使い方には、常駐再生と、逐次供給再生がありますが、
        ループ再生が利用できるのは常駐再生の場合です。
        ストリーム再生モードは未対応です。
        PCM_EntryNext や PCM_Change はこの機能より優先されます。つまりループ
        回数の指定にかかわらず、登録されていた次のハンドルに切り替わります。
        サンプルプログラム smppcm4, smppcm13 に処理例があります。
      3) サンプルプログラムの修正
        サウンドドライバの初期設定をプログラムで行うように修正しました。

Ver.1.15 から Ver.1.16への変更点
      1) 次のバグを修正しました。
        ファイル再生における先読み処理
          ファイルシステムを使って再生する時、PCM_Start より先に PCM_Task を
          コールすると、その後再生を開始しようとして PCM_Start をコールした時
          にＧＦＳにエラーを発生させてしまうバグがありました。
          修正により、再生開始前に PCM_Task をコールしていれば、正常にファイル
          の先読み処理が行えるようになりました。
      2) サウンドＩ/Ｆライブラリの使用
          旧処理：サウンドドライバへのコマンド発行は全て、独自に行う。
                  コマンドブロックは、指定された特定の番号を使用する。
          新処理：サウンドドライバへのコマンド発行は全て、サウンドＩ/Ｆライブラ
                  リを使用して行う。コマンドブロックは特定されない。
          サウンドドライバの仕様変更を吸収させるために、サウンドＩ/Ｆライブラリ
          を使用するように修正しました。今後は sega_snd.lib をリンクする必要が
          あります。
      3) 次の関数が削除されました。
          PCM_SetPcmCmdBlockNo :ＰＣＭコマンドブロック番号の設定
