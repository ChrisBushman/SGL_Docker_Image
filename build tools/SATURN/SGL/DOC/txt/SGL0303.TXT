○slPutPolygon()が正常に動作をしないというトラブルが報告されています。
  原因については現在調査中ですが、対処法については幾つか判明しています。

【症状その１】
     頂点の一部だけが思わぬ方向に飛んでいる。
【対処その１】
     ○4頂点又は3頂点、全てを共有する複数のポリゴンがある場合、
       正常な動作をしない事があります。
     ○計算の頂点数を余分に増やす
          PDATA構造体の頂点数の部分に手をくわえます。

【症状その２】
     動作中、VDP1の動作だけが止まりVDP2は動作する。
【対処その２】
     ○指定したint数内に計算が終わらない場合起きる事があります。
       システム変数SynchCountを調整してください。
       （考えられる最大負荷時のint数を予め設定しておき、処理が終った時点で
         システム変数SynchCountを変更して下さい。）

【症状その３】
     ポリゴンが正常に出力できない。
【対処その３】
     ○4頂点又は3頂点全てを共有する複数のポリゴンがあるかどうか調べる。
     ○slPutPolygonSに置き換えて見てください、正常に出力出来る事があります。
          （メインとスレーブの負荷分担の関係）

※4頂点又は3頂点全てを共有する複数のポリゴンとは？
    例えば、
      POINT point_PLANE1[] = {
        POStoFIXED(-10.0, -10.0, -10.0),
        POStoFIXED( 10.0, -10.0, -10.0),
        POStoFIXED( 10.0,  10.0, -10.0),
        POStoFIXED(-10.0,  10.0, -10.0),
        POStoFIXED(-10.0, -10.0, 10.0),
        POStoFIXED( 10.0, -10.0, 10.0),
        POStoFIXED( 10.0,  10.0, 10.0),
        POStoFIXED(-10.0,  10.0, 10.0)
      };
     という8頂点が与えられた時、
      POLYGON polygon_PLANE1[] = {
        NORMAL(0.0, 1.0, 0.0), VERTICES(0, 1, 2, 3),
        NORMAL(0.0, -1.0, 0.0), VERTICES(0, 1, 2, 3),
        NORMAL(0.0, -1.0, 0.0), VERTICES(4, 5, 6, 7)
      };
     というポリゴン中
        NORMAL(0.0, 1.0, 0.0), VERTICES(0, 1, 2, 3),
        NORMAL(0.0, -1.0, 0.0), VERTICES(0, 1, 2, 3),
     の2つのエントリは、同じ4頂点( 0, 1, 2, 3 )を共有しているので
     4頂点又は3頂点全てを共有する複数のポリゴンとなります。
